# Настройка Supabase для TODM

1. Откройте SQL Editor в проекте Supabase.
2. Выполните `schema.sql` целиком один раз, затем `002_staff_ranks.sql` и `003_avatar_select.sql`. Для уже настроенной базы выполняйте только ещё не применённые миграции.
3. В Authentication → Providers → Email включите регистрацию и отключите Confirm email.
4. В Authentication → URL Configuration укажите production URL GitHub Pages и `http://127.0.0.1:8765/**` для локальной проверки.
5. Зарегистрируйте авторский аккаунт через сайт.
6. Выполните закомментированный `update account_access` из конца `schema.sql`.

Не размещайте secret/service_role key в этом репозитории. Пороговые суммы в `archive_thresholds` намеренно не активированы и содержат технические значения-заглушки.

## Ранги сотрудников

I–III — читатели; IV — сотрудники с плашкой TODM и полным доступом; V — только существующий аккаунт владельца (UUID закреплён в миграции).
Для назначения сотрудника установите `account_access.archive_level = 4`: триггер включит `is_todm_team` и `full_access`, не изменяя `is_admin`.
Для снятия ранга сотрудника установите уровень 0–3: плашка TODM и полный доступ будут сняты. Административные права управляются отдельно.
Простое выключение `is_todm_team` без понижения IV/V не снимает статус команды. V нельзя присвоить другому пользователю даже через Table Editor.
Блокировка `is_banned` продолжает закрывать доступ к материалам при любом ранге. Платежи и пороги поддержки не назначают IV/V.
